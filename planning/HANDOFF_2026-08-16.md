## 3. What the previous handoff got wrong

The document itself is gone; these two quotes from it are recorded here because the same
assumptions will otherwise be made again.

**"A tiny synthetic dataset, 8 epochs, CPU, fixed seed."** There was no fixed seed to be
had. NSM calls no seeding function anywhere; `SDFSamples(random_seed=...)` only feeds the
cache key. Worse, the near-surface sampler — the one every shipped config uses — could not
be seeded by any caller. The harness therefore runs the *uniform* sampling path, which is
seedable. Closing that gap is §4.

**"Pin the current behaviour, bugs included, in a characterization test."** Done as
written, this made ~20 tests pass *because* something was broken, so a green suite reported
the opposite of the truth. They now assert the behaviour NSM *should* have, marked
`xfail(strict=True)`. See §5.

magnitude, widen the break rather than loosening the tolerance.

## 5. What to understand before touching the harness

**Green means "nothing changed", not "the library is correct."** Three outcomes:
`passed` = correct or unmoved; `xfailed` = known defect, still present; `failed` = a
regression **or a defect you just fixed**. All 20 xfails are `strict=True`, so fixing one
XPASSes and turns the suite red until its mark is removed. That is deliberate — it stops
"known defect" from decaying into "permanently ignored". The workflow is at the top of
`DEFECT_WORKLIST.md`.

**Baselines are pinned to Linux-x86_64** and *skip* elsewhere; a torch or numpy change
*fails* instead. That asymmetry is intentional — a dependency bump that moves training
output is what the harness is for. Regenerating on another platform refuses rather than
clobbering. Adding macOS means adding a per-platform baseline file, **not** loosening
tolerances until both fit.

**The harness has been seen to fail**, which is the only reason to trust it. Reverting
`adjust_learning_rate` to its pre-Aug-2026 positional mapping produces 14 failures across
both halves. Two deliberate breaks are asserted on every run.

**Things that will cost you an hour** (the rest are in the README):

- `reconstruct_mesh` calls `decoders[i].to(device)`, which moves a module **in place**.
  Hand it a copy, never a session-scoped fixture.
- `loc_save`'s default is read from `LOC_SDF_CACHE` *at import time*. Setting the env var
  in a test is too late and writes to your real `~/.cache/nsm_sdf_cache`. Always pass
  `loc_save` explicitly.
- `_harness.build_model` imports the private `loader._get_triplanar_params` because NSM has
  no public "build the model this config describes" call. When the decoder registry lands,
  that import is what should fail loudly.
- `run_training` wraps `train_epoch` because `train_deep_sdf` returns `None`. Fixing
  worklist #11 lets you delete the wrapper.

## 6. What not to do

- **Do not loosen a tolerance to make something pass.** Tolerances were sized from measured
  break magnitudes, not taste; the table is in the README. If a baseline fails, find out why.
- **Do not delete an `xfail` mark to get to green.** A red XPASS means you fixed something;
  go tick the worklist entry.
- **Do not fix a defect and a behaviour in the same commit as a refactor.** Worklist #1
  (cache key) needs a `docs/KNOWN_ISSUES_HISTORY.md` entry, because it silently changes
  training output for inputs that previously ran.
- **Do not fix worklist #1 before #3.** Fixing the cache key forces every cache entry to
  regenerate, and until sampling is reproducible, regeneration produces *different* data
  rather than the same data.
- **Worklist #9 (VAE layer aliasing) is a checkpoint-format break in both directions** —
  verified. Old checkpoints get `Unexpected key(s)`, new ones `Missing key(s)`. All three
  shipped models are affected. It needs a migration shim, not a one-line fix.
